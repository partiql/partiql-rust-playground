# PartiQL Playground (Proof of Concept)

PartiQL Playground provides the functionality to execute PartiQL in a web environment.

_Please note, at this stage, the code as is in this package is considered experimental and should not be used for production._

:raised_hands: Checkout the [playground](https://partiql.org/playground.html#/evaluate) now :raised_hands:. 

## Development
This repository contains the Rust code compiled to [WebAssembly (Wasm)](https://webassembly.org/) that runs
PartiQL in the browser. The web front-end lives in
[partiql.github.io](https://github.com/partiql/partiql.github.io) (`ui/playground`).

Prerequisites: Rust with the `wasm32-unknown-unknown` target, [wasm-pack](https://rustwasm.github.io/wasm-pack/)
and Node.js (for the smoke test).

```commandline
make build        # wasm-pack build --target web --out-dir pkg-web/
make smoke-test   # build, then run tests/smoke.mjs against pkg-web/
```

## Releasing the Wasm package for the website
The website does not vendor the Wasm build. It downloads a pinned, checksummed release asset from this
repository:

```
https://github.com/partiql/partiql-rust-playground/releases/download/v<version>/partiql-playground-web-<version>.tar.gz
```

The archive holds the `wasm-pack --target web` output (`partiql_playground.js`, `partiql_playground_bg.wasm`,
typings), `LICENSE`, `NOTICE`, `THIRD_PARTY_LICENSES.txt` (generated by
[cargo-about](https://github.com/EmbarkStudios/cargo-about) from `about.toml`/`about.hbs`) and
`build-info.json` (version, commit, PartiQL and wasm-bindgen versions). A `.sha256` file is published
alongside it. The build is reproducible: building the same commit (toolchain pinned in
`rust-toolchain.toml`, dependencies in `Cargo.lock`, same wasm-pack) gives byte-identical files; only the
gzip compression of the archive can vary with the platform's zlib.

To release:
1. Bump `version` in `Cargo.toml`, update `CHANGELOG.md`, and merge to `main`.
2. Tag the merge commit `v<version>` and push the tag. The
   [release workflow](.github/workflows/release.yml) builds the package, runs the smoke test, and creates the
   GitHub release with the archive attached. The workflow fails if the tag doesn't match `Cargo.toml` or
   isn't on `main`. If it fails midway, re-run it: the release stays a draft until its assets are uploaded.
   A published release is never changed; release a new version instead.
3. In partiql.github.io, update the version and `sha256` in `ui/playground/engine.json`.

To build the archive locally (needs `cargo install --locked --features cli cargo-about@0.9.2`, the version the release workflow uses):

```commandline
make package      # dist/partiql-playground-web-<version>.tar.gz and .sha256
```
